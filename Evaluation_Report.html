3. Failure Modes Discovered

#FailureRoot CauseFix Applied
1 LLM answers from training data instead of RAG context System prompt not restrictive enough — model "knew" general facts about common tech stacks Added strict grounding rule: "ONLY answer from retrieved context. If not in context, say you don't know."
2 Booking widget renders on every response including "hi" Llama 3.1 8B over-compliant — interprets any mention of "interview" as booking intent Client-side keyword gate + prompt narrowed to explicit booking verbs only (book/schedule/availability)
3 Vapi tool calls returning 405 error Vapi migrated from function-call to tool-calls webhook event format Added handler for tool-calls type with toolCallList parsing + kept legacy support

4. Key Tradeoff

Model Size: 8B (chat) vs 70B (voice)

Chat has RAG context injected, reducing reasoning load — 8B delivers accurate responses with ~200ms LLM latency. Voice requires stronger reasoning for multi-turn booking flows and tool-call decisions — 70B model justified despite 2× latency. Both on Groq free tier ($0 cost), but 8B keeps chat total response under 2s while 70B ensures voice task completion at 7/10 rate.
